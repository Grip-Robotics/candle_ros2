# Opening-stop homing and removal of saved-state recovery

User approved opening-stop homing at 2 rad/s and 0.5 Nm, then requested it on
every driver launch and motor-power recovery, with no shutdown state persistence.
Branch remains `feature/continuous-impedance-close`; nothing committed/pushed.

## Implemented behavior

- `/md/home` accepts one ID and replies after completed homing, not just an ACK.
  GRIP calls it sequentially in scene order before readiness (113, 447, 111 here).
- With `homing_required=true`, normal motion/init/enable cannot bypass a missing
  reference. Motor communication recovery queues sequential homing; no previous
  grasp is replayed. Explicit disable cancels pending automatic homing. A failed
  search leaves the reference invalid and requires an explicit retry.
- Reuses the opening ramp and windowed contact evidence: 2 rad/s speed limit,
  0.5 Nm total firmware torque cap, no I/floor, 0.85 rad relative search bound,
  2 s search deadline, directional torque >=0.35 Nm for 0.25 s with settled
  position range/window-average velocity. A jam can still resemble the stop.
- After detection: clear PD/torque, disable, allow <=0.05 rad passive rebound.
  Require a 0.005 rad position window, low average velocity and torque <0.1 Nm
  for 0.25 s, within a separate 2 s deadline. Zero the relaxed open position once
  while disabled, verify readback within 10 ms, restore normal limits, release
  at 0 Nm and retain monitoring. No flash save.
- Removed persistent store/checkpoints/state-file options and Docker mount.
  Historical JSON files and the old Docker volume were not deleted.
- Generic defaults retain `homing_required=false`; MD20/GRIP profiles enable it.
  Standalone users add known IDs and home before init; merely starting a bare
  process does not scan for and move unknown motors.

## Hardware issues found and fixed

1. Firmware represents unrestricted position limits as +/-FLT_MAX, not just
   zero/zero. Initial preflights rejected this without enabling. Both forms now
   pass; genuinely restrictive firmware limits are not silently removed.
2. Stationary velocity noise reached 0.051 rad/s with only 0.000192 rad position
   variation in 0.5 s. Per-sample settling timed out without zeroing. Homing now
   uses existing windowed contact evidence; ordinary opening remains unchanged.
3. Zero acknowledgment precedes the encoder-register update. Bounded readback
   polling now checks the new frame rather than treating the ACK as completion.
4. Releasing the loaded stop caused about 0.026 rad rebound on 113. Zero now
   follows bounded relaxed settling, avoiding a reference defined under load.
